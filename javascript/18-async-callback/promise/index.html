JavaScript Async Course

Part 2 — Promises & Async/Await

The upgrade from callbacks

A Promise represents a result that will exist later.

Instead of nesting callbacks, you can create a Promise, wait for it, handle success, and handle failure in a much cleaner way.

Promise states

Pending — still working
Fulfilled — success
Rejected — failure

1. What is a Promise?

Imagine ordering food. You do not stand inside the kitchen waiting. You place the order and receive a promise: “I will give you the food later.” JavaScript Promises work with the same basic idea. 

const promise = new Promise((resolve, reject) => {

  // do some work

  if (everythingIsOkay) {

    resolve("Success!");

  } else {

    reject("Something went wrong.");

  }

});

Pending

The asynchronous operation has started but has not finished.

Fulfilled

The operation finished successfully. The Promise has a value.

Rejected

The operation failed. The Promise has a reason/error.

2. resolve() and reject() 

function getData() {

  return new Promise((resolve, reject) => {

    setTimeout(() => {

      const success = true;

      if (success) {

        resolve("Data received!");

      } else {

        reject("Request failed!");

      }

    }, 1000);

  });

}

resolve(value) means success. reject(error) means failure.

3. then() and catch() 

getData()

  .then((data) => {

    console.log(data);

  })

  .catch((error) => {

    console.error(error);

  });

then() handles success. catch() handles rejection/errors.

4. Promise chaining

A major advantage is that one asynchronous result can feed the next operation. 

loginUser()

  .then((user) => {

    return getProfile(user);

  })

  .then((profile) => {

    return getOrders(profile);

  })

  .then((orders) => {

    return getFirstOrder(orders);

  })

  .then((order) => {

    console.log("Final order:", order);

  })

  .catch((error) => {

    console.error("Something failed:", error);

  });
Login
→ Profile
→ Orders
→ First order

5. Important: async functions always return Promises 

async function hello() {

  return "Hello!";

}

const result = hello();

console.log(result);

// Promise { "Hello!" }

Even though you wrote return "Hello!" , the async function wraps that value in a Promise.

6. await

await waits for a Promise to settle inside an async function. It makes asynchronous code read from top to bottom. 

async function showData() {

  const data = await getData();

  console.log(data);

}

showData();
Think: “Give me the result of this Promise before I continue this async function.”

7. try...catch

When using await, a rejected Promise can be handled with normal-looking try/catch. 

async function showData() {

  try {

    const data = await getData();

    console.log(data);

  } catch (error) {

    console.error(error);

  }

}

8. Chaining async operations with await 

async function loadDashboard() {

  try {

    const user = await loginUser();

    const profile = await getProfile(user);

    const orders = await getOrders(profile);

    const firstOrder = await getFirstOrder(orders);

    console.log(firstOrder);

  } catch (error) {

    console.error("Something failed:", error);

  }

}

Compare this with callback hell. The dependency is still there, but the nesting is gone.

9. Mixing async/await with then/catch

You technically can mix them because async/await is built on Promises, but beginners should usually choose one style per flow for readability. 

async function example() {

  const data = await getData();

  return processData(data);

}


example()

  .then((result) => {

    console.log(result);

  })

  .catch((error) => {

    console.error(error);

  });
This is not automatically wrong. The important point is understanding that async/await and then/catch both work with Promises.

12. Common beginner confusions

“async means the function runs in parallel.”

Not exactly. async changes how the function returns a Promise and enables await.

“await blocks all JavaScript.”

No. await pauses the current async function while the rest of the environment can continue.

“then and await are unrelated.”

They are two ways of consuming Promise results.

Final mindset

Async isn't magic — it's structured waiting.

Start a task → receive a Promise → wait for its result → handle success or failure → continue to the next operation.

Beginner checklist

Don't just read the code — change the delays, values, and errors and run it again.
