JavaScript Async Course

Part 1 — Callbacks

Beginner friendly

The big idea

JavaScript can start something now and finish it later.

A callback is simply a function that you give to another function so that it can call your function later, usually after some work has finished.

Mental model

1. Start a task
2. Give it a callback
3. JS continues
4. Callback runs later

1. Synchronous vs asynchronous

First understand the problem before learning the solution.

Synchronous

Code normally runs from top to bottom. If line 2 takes time, line 3 waits. 

console.log("A");
console.log("B");
console.log("C");

// A
// B
// C

Asynchronous

A slow operation can be started while JavaScript continues with other work. 

console.log("A");

setTimeout(() => {
  console.log("B");
}, 1000);

console.log("C");

// A
// C
// B

2. What exactly is a callback?

A callback is not a special JavaScript type.

It is just a normal function passed as an argument to another function. 

function greet(name) {
  console.log("Hello " + name);
}

function processUser(callback) {
  const name = "Animesh";
  callback(name);
}

processUser(greet);
Read it like English: “processUser, here is the function I want you to call when you are ready.”

4. Callback with success + error

Before Promises became common, a callback often received two arguments: an error first, then the successful result. 

function getUser(id, callback) {
  setTimeout(() => {

    if (id === 1) {

      callback(null, {
        id: 1,
        name: "Alex"
      });

    } else {

      callback("User not found", null);

    }

  }, 1000);
}

getUser(1, (error, user) => {

  if (error) {
    console.log(error);
    return;
  }

  console.log(user);

});

5. Callback hell

When asynchronous tasks depend on each other, callbacks can become deeply nested. The code starts looking like a staircase or pyramid. 

loginUser((user) => {

  getProfile(user, (profile) => {

    getOrders(profile, (orders) => {

      getFirstOrder(orders, (order) => {

        sendInvoice(order, (invoice) => {

          console.log(invoice);

        });

      });

    });

  });

});
Problem: harder to read, harder to handle errors, and harder to maintain. This is one reason Promises became popular.
